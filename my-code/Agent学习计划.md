# 从第七章到毕业设计：Agent 开发学习计划

## 目标

从第七章开始，掌握独立开发 Agent 应用所需的框架、运行时、应用形态、工具、Skill、记忆、上下文工程、MCP 与多 Agent 协作能力，完成一个可运行、可复现、可评估的毕业设计项目。

Python 已具备，因此不以“逐章读完”为目标，而以可交付的实作成果为目标。

## 推荐节奏

- 高强度学习：5–6 周，每周 20–25 小时。
- 业余学习：10–12 周，每周 8–10 小时。
- 每个阶段完成最小产物即可进入下一阶段；扩展功能作为加分项，不阻塞进度。
- 实践采用固定的“三步法”：**复现一次 → 改造一次 → 脱离教程从零写一次**。

## 章节优先级

### 必须精做

1. 第7章：框架接口、ReAct、工具系统。
2. 第8章：记忆、RAG、文档问答助手。
3. 第9章：上下文工程、结构化笔记、受控终端工具。
4. 第10章：优先 MCP；再做最小 A2A 双 Agent 协作；ANP 先理解概念。
5. 第12章：从第一个可运行版本开始维护评测集，不要等项目结束才评估。
6. 第14章：作为产品化架构范本，重点研究规划、搜索调度、报告生成、工具事件和进度展示。
7. 第16章：按毕业设计的 README、可复现、演示和评估要求完成交付。

### 选择性学习

- 第13章：用于补齐 FastAPI、数据模型、前后端分离和多 Agent 产品结构。
- 第15章：只在想做游戏或模拟应用时学习；Godot 部分不属于通用 Agent 开发的必修内容。
- 第11章：暂缓。Agentic RL 属于训练和后训练路线，不是先做出可靠 Agent 应用的前提；毕业设计完成后再决定是否需要。

### 需要补充的 Skill 内容

- `Extra-Chapter/Extra05-AgentSkills解读.md`：理解 Skill 与 MCP 的边界和协作方式。
- `Extra-Chapter/Extra08-如何写出好的Skill.md`：学习渐进式披露、约束设计和可复用 Skill 的创建流程。
- `Extra-Chapter/Extra09-Agent应用开发实践踩坑与经验分享.md`：学习工具粒度、权限、可观测性、上下文和提示词的工程经验。

## 必须建立的心智模型

- **Tool**：单次、可验证的外部动作，例如搜索、读取文件、生成图表。
- **Skill**：可复用的工作方法、领域规则、操作约束、示例及配套资源。
- **Agent Runtime**：任务运行机制；负责决定读取哪些 Skill、调用哪些 Tool、如何保留状态、何时停止、失败后如何恢复。
- **Agent 应用**：将 Runtime 包装为用户可使用的形态，例如 CLI、Web、聊天机器人、定时任务或 API 服务。

## 推荐毕业设计

建议项目：**带私有知识库的深度研究与行动助手**。

它能以较小范围覆盖所有关键能力：RAG、记忆、上下文、MCP、工具执行、多 Agent、任务进度和评估。

```text
用户问题
  → Planner：拆分任务、定义验收
  → Researcher：检索 / RAG / 标注来源
  → Executor：调用受控工具，生成文件或报告
  → Reviewer：检查事实、引用、格式和遗漏
  → 结果页：显示流式进度、报告和可追溯执行记录
```

### 项目范围控制

1. 最小版：研究一个问题并输出带引用的 Markdown 报告。
2. 第二版：加入本地文档知识库与跨会话记忆。
3. 第三版：加入 MCP 工具、规划 Agent 与审查 Agent。
4. 完整版：加入 Web 界面、任务历史、评测集、成本和延迟记录。

不要一开始做复杂的多 Agent 网络、训练模型、精致前端或部署。先让最小闭环可靠运行。

## 每周执行看板

- **必做**：本阶段最小产物可运行。
- **加分**：测试、结构化 Trace、UI、更多工具或更多 Agent。
- **暂缓**：训练、复杂前端、生产部署、大规模 Agent 编排。
- **升级条件**：连续通过 5 个真实任务后再进入下一阶段；失败时优先修工具边界、状态记录和评测，不先堆提示词。

## 各阶段验收问题

### 阶段 1–2：Agent 与 Runtime

- 我能解释消息、提示词、工具 schema、工具结果和状态分别放在哪里吗？
- Agent 调用错误工具、参数不合法、工具超时、模型输出不符合格式时，会发生什么？
- 我能在不依赖教程代码的情况下新增一个 Tool 吗？

### 阶段 3：记忆与上下文

- 我是否能说明“记忆”和“本次请求上下文”的区别？
- 回答是否有依据与来源？
- 文档很多时，是否仍能控制提示词长度和成本？

### 阶段 4：协议与协作

- MCP Server 挂掉、返回异常或提供危险工具时，系统如何处理？
- 多 Agent 的职责是否明确，是否存在重复工作或无法结束的循环？

### 阶段 5–7：产品交付

- 一个从未看过代码的人能否按 README 启动项目？
- 用户能否看到当前任务阶段、调用失败原因和最终产物？
- 是否有固定任务集，能证明改动没有让能力退化？
